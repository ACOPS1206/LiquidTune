# LiquidTune 검증 기록

## 3.0 빌드 60

플레이어, 가사, 대기열 전환에 슬라이드와 교차 페이드를 적용했습니다.
iOS의 동작 줄이기가 켜져 있으면 페이드만 사용합니다. 가로 가사
화면의 메뉴에서 대기열을 바로 열 수 있습니다.

Swift 코어 테스트 12개가 통과했고 Jellyfin 실서버 테스트 1개는
건너뛰었습니다. 전환의 실기기 표시는 미검증입니다.

## 3.0 빌드 59

Xcode의 Debug·Release 설정과 교차 빌드 IPA의 번들 ID를 `dev.acops.liquidtune`으로 변경했습니다. 실기기 설치는 미검증입니다.

## 3.0 빌드 58

첨부한 iOS 아이콘 PNG를 기본·다크·틴트 슬롯에 연결했습니다. 투명한
가장자리는 배경색으로 채우고, 틴트 이미지는 시스템이 착색할 수 있도록
회색조로 바꿨습니다. 교차 빌드 IPA는 빌드 57의 실행 파일을 사용하고
기본 아이콘을 새 렌더링으로 교체했습니다. Xcode 자산 컴파일과
실기기 홈 화면 표시는 미검증입니다.

## 3.0 빌드 57

앱 표시 이름을 LiquidTune으로 바꿨습니다. Xcode 타깃의 기본
아이콘은 사용자가 제공한 `LiquidTune.icon`입니다. 교차 빌드 IPA는
첨부 아이콘의 색과 도형을 평면 PNG로 렌더링해 포함합니다. Xcode의
레이어 컴파일과 실기기 홈 화면 표시는 미검증입니다.

## 3.0 Instant Mix와 앱 이름

곡 목록과 재생 화면 메뉴에서 현재 곡을 기준으로 Instant Mix를 시작할
수 있습니다. Jellyfin 추천 요청과 응답 중복 제거, 로컬 추천의 아티스트·
장르 일치와 추천 수 제한을 Swift 테스트로 확인했습니다.

iOS arm64 교차 빌드와 IPA 구조 검증을 완료했습니다. Swift 코어
테스트는 12개 통과했고 Jellyfin 실서버 테스트 1개는 건너뛰었습니다.
실기기에서 이름 표시, 기존 앱 위 설치, Instant Mix 재생은 미검증입니다.

## 0.2.44 강조색, 검색 위치, 대기열 상단

탭과 곡 메뉴의 강조색을 흰색·검은색으로 바꾸고, 현재 재생 중인 줄을
중립색으로 강조합니다. 밝은 계열의 앨범 배경에는 검은 글자와 아이콘을
표시합니다. 검색은 홈 상단에서 열고 보관함에는 검색 창을 표시하지
않습니다. 대기열 상단은 셔플·반복·편집 캡슐 버튼을 제공하며 활성 상태에
앨범 아트의 강조색을 사용합니다.

Swift 코어 테스트 10개가 통과했고 Jellyfin 실서버 테스트 1개는
건너뛰었습니다. 시뮬레이터와 실기기 렌더링은 미검증입니다.

## 0.2.43 앨범 배경의 색상 선정

앨범 표지의 픽셀을 색상 계열로 묶어 표본 수가 가장 많은 두 그룹의
평균색을 그라데이션에 사용합니다. 제공된 Starboy 스크린샷에서 표지만
잘라 동일한 분류 규칙으로 분석했을 때 어두운 계열과 빨간색이
1위와 2위였습니다. 이 비교는 이미지 표본 분석이며 iOS 렌더링은
미검증입니다.

Swift 코어 테스트는 10개 통과했고 Jellyfin 실서버 테스트 1개는
건너뛰었습니다.

## 0.2.42 앨범 배경과 버튼 높이

앨범 상세 배경을 표지의 대표색 두 가지를 잇는 그라데이션으로
표시합니다. 재생, 셔플, 추가 버튼의 높이를 모두 48pt로 지정했습니다.
재생 버튼은 흰색 캡슐 모양을 유지합니다.

Swift 코어 테스트는 10개 통과했고 Jellyfin 실서버 테스트 1개는
건너뛰었습니다. 시뮬레이터와 실기기 렌더링은 미검증입니다.

## 0.2.41 앨범 표지 색과 재생 버튼

앨범 상세의 재생 버튼을 흰색으로 표시하고, 검은색 재생 아이콘과
라벨을 버튼 안에 배치합니다. 양옆의 셔플과 추가 버튼에 같은 너비를
할당해 재생 버튼을 화면 가운데에 둡니다. 배경은 표지에서 대표 색을
최대 세 가지 추출해 화면의 시스템 배경색 위에 그라데이션으로
표시합니다. 표지가 없거나 색을 추출할 수 없으면 시스템 배경색을
사용합니다.

iOS arm64 교차 빌드와 IPA 구조 검증을 통과했습니다. Swift 코어
테스트는 10개 통과했고 Jellyfin 실서버 테스트 1개는 건너뛰었습니다.
시뮬레이터와 실기기 렌더링은 미검증입니다.

## 0.2.40 앨범 상세

홈, 보관함, 검색에서 전용 앨범 상세 화면을 엽니다. 큰 표지와 앨범
정보, 재생·셔플·추가 버튼, 트랙 번호와 곡별 메뉴를 표시합니다. 앨범
추가 메뉴는 대기열과 기기 내 플레이리스트를 지원합니다. 0.2.39의
베이스 배경 면적 제한을 되돌려 0.2.38의 효과를 복원했습니다.

Swift 코어 테스트는 10개 통과했고 Jellyfin 실서버 테스트 1개는
건너뛰었습니다. iOS 시뮬레이터와 실기기 화면 및 버튼 동작은 미검증입니다.

## 0.2.39 베이스 배경의 면적 제한

회전한 색 영역을 화면 좌표로 합성하고 가장자리를 부드럽게 만든 후,
마스크의 활성 샘플을 최대 25%로 제한합니다. 화면 전체가 같은 어두운
색으로 채워진 경우 효과를 억제합니다. 실제 iPhone 렌더링은 미검증입니다.

## 0.2.34 저역 반응 배경

가사 화면의 진행 바에서는 경과·남은 시간의 시각 표시를 숨깁니다.
플레이어 앨범 아트의 그림자를 제거했습니다. 배경 효과는 재생 중 접근
가능한 PCM의 저역 상승을 감지해 0.18초 동안 확장하고 1.12초 동안
감쇠합니다. 앨범 아트 색 옵션과 동작 줄이기 설정을 따릅니다.
합성 75Hz 자극과 1.5kHz 신호로 감지 조건을 확인했으며, 실기기
재생과 스트리밍의 PCM 제공 여부는 미검증입니다.

## 0.2.30 웹 데모 가사 전환 이식

웹 데모의 `updateLyrics` 알고리즘을 SwiftUI에 이식했습니다. 줄의 전환 전
좌표와 다음 레이아웃 좌표의 차이를 구해, 580ms 곡선과 최대 네 단계의
44ms 지연으로 애니메이션합니다. CSS의 화면 비례 간격, 자간, 줄 높이,
세로 32%와 가로 41.6%의 가사 기준점을 적용했습니다. 실기기에서의
렌더링과 전환은 미검증입니다.

## 0.2.13 홈과 가사 크기

홈은 현재 음악 소스의 앨범을 추천 카드로 표시합니다. 재생 기록이
있으면 최근 재생 섹션의 제목을 눌러 전체 기록 목록을 열 수 있습니다.
가사 기본 크기는 동기화 18.9pt, 일반 18pt입니다. 실기기 레이아웃과
가로 스크롤은 미검증입니다.

## 0.2.10 가사 크기와 블러

기본 글꼴을 동기화 가사 63pt, 일반 가사 60pt로 조정했습니다.
자동 따라가기 중 현재 줄 아래의 가사를 거리에 따라 흐리게 표시합니다.
직접 스크롤하거나 VoiceOver를 사용하면 가사를 선명하게 표시합니다.
iPhone에서의 렌더링과 스크롤은 미검증입니다.

## 0.2.9 플레이어 손잡이와 가사

상단 손잡이를 탭하거나 아래로 끌어 플레이어를 닫습니다. 짧게 끌면
원래 위치로 돌아옵니다. 가사 기본 크기는 동기화 가사 42pt, 일반 가사
40pt입니다. 실기기에서의 제스처와 가사 레이아웃은 미검증입니다.

## 0.2.8 가사 시작 위치와 글꼴 크기

가사 영역 상단부터 표시하며, 동기화 가사의 자동 따라가기도 상단을
기준으로 합니다. 기본 가사 글꼴 크기를 네 배로 늘렸습니다. 시간
정보가 있는 가사는 84pt, 일반 가사는 80pt이며 Dynamic Type을 따릅니다.
실기기에서의 레이아웃과 스크롤은 미검증입니다.

## 0.2.7 가사 정렬과 자동 스크롤

가사는 왼쪽에 정렬합니다. 동기화 가사의 기본 글꼴 크기는 21pt이고
Dynamic Type을 따릅니다. 재생 중 현재 줄이 바뀌면 뷰 중앙으로 부드럽게
이동합니다. 직접 스크롤하면 따라가기를 멈추고, 오른쪽 아래 아이콘을
누르면 재개합니다. 동작 줄이기나 VoiceOver를 사용하면 스크롤
애니메이션을 적용하지 않습니다. 실기기에서 화면과 동작은 미검증입니다.

## 0.2.6 가사와 대기열

두 화면에서 작은 앨범 아트 옆에 곡 정보와 재생 위치를 표시합니다.
앨범 아트를 누르면 기본 플레이어로 돌아가고, 곡 메뉴에서 재생을
일시 정지하거나 다시 시작할 수 있습니다. 동기화 가사는 현재 줄을
가운데로 이동시키고, 수동 스크롤 뒤 따라가기 버튼을 제공합니다.
대기열은 다음 곡부터 표시하며 곡별 재생과 제거, 편집 모드의 순서 변경을
지원합니다. 재생 시간 정보가 있는 경우에 길이를 표시합니다.

iPhone에서의 실제 화면과 제스처는 미검증입니다.

## 0.2.5 플레이어 조작부

일반 세로 화면에 앨범 아트, 재생 위치, 재생 버튼, 하단 도구를 세로로
배치합니다. 셔플과 반복은 재생 버튼 양쪽에 있으며 하단에서 속도, 음량,
오디오 출력, 가사, 대기열을 엽니다. 선택된 가사 또는 대기열 아이콘을
다시 누르면 아트워크로 돌아갑니다. 재생 위치 아래에는 단일 파일 형식이
알려진 트랙에서만 형식을 표시합니다. 실기기 레이아웃과 출력은 미검증입니다.

## 0.2.4 전체 화면 플레이어

설정에서는 정지합니다. 실제 기기의 애니메이션 표현은 확인하지 못했습니다.

## 0.2.1 Jellyfin 가사

모의 Jellyfin 응답으로 인증, 경로, 타임스탬프 변환과 경계값, 일반 가사,
가사 없음 상태를 확인했습니다. iPhone에서의 화면, 실제 서버 가사 재생과
싱크는 이 작업 환경에서 실행하지 않았습니다.

## 공통 로직과 Jellyfin 재현

```bash

```

기본 실행은 실제 서버 테스트를 건너뜁니다. 나머지 9개는 네트워크 없이 동작합니다. 실제 서버 테스트는 테스트 계정과 앨범 표지가 있는 음악을 준비해 실행합니다. 로그인 비밀번호는 명령줄 인수로 전달하지 않습니다.

export TWELVE_JELLYFIN_URL=http://127.0.0.1:8096
export TWELVE_JELLYFIN_USER=twelvetest
export TWELVE_JELLYFIN_TRACK='Orbit Tone'
export TWELVE_JELLYFIN_PLAYLIST='Twelve Queue Fixture'

export TWELVE_JELLYFIN_PASSWORD
swift test --filter testLiveJellyfinAudioArtworkAndSearch
unset TWELVE_JELLYFIN_PASSWORD

플레이리스트 검증을 생략하려면 `TWELVE_JELLYFIN_PLAYLIST`를 설정하지 않습니다. 실제 테스트는 범위 헤더가 있는 오디오 요청을 전송하고 응답 바이트를 확인합니다. 바이트 수신 검증과 AVPlayer 디코딩 검증은 별개입니다.

## iPhone·iPad 확인 순서

1. [README](../README.md) 명령으로 시뮬레이터 빌드를 수행한 다음 Xcode에서 iPhone 및 iPad 시뮬레이터에 실행합니다. Activity, Library, 전체 플레이어를 라이트·다크 및 가로·세로에서 확인합니다.
2. FFmpeg가 설치된 Mac에서 `./Scripts/create-test-audio.sh`를 실행합니다. 생성된 4개 파일을 Files로 옮기고 앱에서 가져옵니다. 제목과 앨범 태그, 재생 소리, 탐색, 다음·이전 전환을 확인합니다.
3. 로컬 파일을 재생한 상태에서 파형을 켭니다. 밝기와 표지가 다른 앨범으로 전환해 앨범 아트 및 테마를 확인하고, 같은 곡을 대기열에 여러 번 넣어 순서 변경과 제거를 확인합니다.
4. iPhone에서 음악을 재생한 채 홈 화면으로 이동한 다음 화면을 잠급니다. 잠금 화면과 제어 센터에서 제목, 일시정지, 다음 곡, 탐색 위치를 확인합니다. AirPlay 피커와 Bluetooth 이어폰을 각각 연결하고 이어폰을 분리했을 때의 동작을 확인합니다.
5. 중간 위치에서 일시정지한 뒤 앱을 종료하고 다시 엽니다. 대기열, 선택 곡, 위치, 반복, 셔플이 복원되고 Play를 눌렀을 때 해당 위치에서 재개되는지 확인합니다.
6. Jellyfin 또는 Subsonic 서버를 앱에서 직접 등록합니다. 로그인, 라이브러리, 플레이리스트, 검색, 표지, 실제 출력과 실시간 탐색을 확인합니다. 네트워크를 끊었다 다시 연결해 재시도와 오류 표시도 확인합니다.
7. iPhoneOS Release를 빌드한 뒤 unsigned IPA 스크립트를 실행하거나 Xcode Organizer에서 서명된 IPA를 내보냅니다. 실기기 설치와 시작 화면 표시까지 확인하면 패키지 런타임 검증이 완료됩니다.
